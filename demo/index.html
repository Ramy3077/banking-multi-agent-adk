      How these were recorded

      Each scenario was run through ADK's InMemoryRunner with the repo's real agents and prompts, using BANK_BACKEND=sqlite. A runner plugin saved every event, including those from bq_agent, which runs inside an AgentTool. Each scenario started from a fresh copy of the seed database. Nothing on this page calls a model.

      In the demo backend, bq_agent answers with three read-only SQL tools over SQLite instead of ADK's BigQuery toolset, and search_places is a local stand-in for the Google Maps tool that only knows fictional locations. Every customer, merchant and address is made up. Timings are wall-clock from the recording, so they include model latency.

      Script: scripts/record_sessions.py. Raw traces: sessions/.
